# 消费者问题地图

本文件用于把常见消费者问法转换成报告检索任务。它只帮助理解用户关心什么，不作为老乡鸡经营事实依据。最终回答必须回到 `report-text.md` 或 `report.pdf` 核对。

## 常见关切

公开讨论里，用户常关心：

- 老乡鸡到底是不是“预制菜”
- 具体菜品是门店现做、半预制，还是复热预制
- 哪些菜到店后主要是复热
- 能不能看到原料来源、供应商、加工步骤、检测报告
- 中央厨房加工算不算预制菜
- 食品安全事件后，报告有没有回应原料真实性、肉类来源、新鲜度等担忧
- 配料信息、配料合规和检测信息能不能看到
- 菜品是否新鲜、是否可能过期、是否有异物
- 热量、钠、蛋白质、脂肪等营养信息能不能看到
- 堂食、外卖、小程序能不能扫码看溯源
- 报告披露的是不是实时信息
- 顾客关于卫生、分量、服务的反馈有没有被披露和改善

## 问法转换表

| 用户问法 | 报告检索目标 | 回答边界 |
| --- | --- | --- |
| “是不是预制菜” | `加工等级`、`餐厅现做`、`半预制`、`复热预制` | 不要简单答是/不是，要按报告分类解释。 |
| “哪些菜是预制/复热” | `复热预制`、具体菜品页的 `加工等级` | 只代表报告版本，不代表实时菜单。 |
| “某道菜怎么做” | 菜名、`餐厅操作工艺`、`制作工艺` | 不要替换成家常菜谱，除非用户明确要家常做法。 |
| “中央厨房算不算预制菜” | `中央厨房`、`原料加工`、加工等级定义 | 解释报告口径；监管或法律定义需要外部来源。 |
| “肉类来源是否可靠” | 具体菜品原料来源、肉类供应商、检验报告 | 只能说报告公开了什么，不能做绝对安全保证。 |
| “配料是否清楚、合规” | `配料`、`检验报告`、具体原料页 | 只引用报告列出的配料或检测信息。 |
| “新不新鲜/会不会过期” | `原料配送`、`配送周期`、`冷链运输`、检测与风险信息 | 报告能说明溯源和配送周期，不能证明实时批次状态。 |
| “能不能看到供应商” | `原料来源`、供应商名称、菜品溯源卡 | 如需列举，必须引用具体菜品页的供应商。 |
| “扫码能看什么” | `二维码`、`菜品溯源卡`、`食材检验报告` | 不承诺所有渠道都覆盖，除非报告明确说明。 |
| “热量/钠/营养” | `营养成分`、具体菜名 | 必须保留报告里的单位和统计口径。 |
| “分量少/卫生差/投诉” | `顾客反馈`、`改善`、相关披露 | 报告没覆盖具体投诉时，答“报告未明确说明”。 |

## 消费者友好回答规则

- 先回应用户关心点，再讲报告分类。
- 依赖报告口径时，用“按报告口径”“报告显示”“报告公开”。
- 避免说“事实就是”，优先说“报告能确认的是”。
- 遇到指控类问题，平静说明可核对的信息和不能下结论的部分。
- 用户说法比报告更宽时，给一个更稳妥的建议表述。

## 示例转换

用户：“老乡鸡是不是全是预制菜？”

回答方向：查加工等级总览。解释报告将菜品分为餐厅现做、半预制、复热预制等类别；如果报告显示多种类别，“全是预制菜”就过于绝对。

用户：“梅菜扣肉是不是后厨现烧的？”

回答方向：查 `梅菜扣肉`。按该菜品页解释加工等级、中央厨房处理、冷链配送、门店蒸制流程。

用户：“我怎么知道它肉是不是安全？”

回答方向：查具体肉类菜品、原料来源、供应商、检测/检验字段和溯源卡说明。补充边界：报告是公开披露依据，不是实时批次安全保证。

## 网络关注来源摘要

这些关切来自公开网络讨论的归纳，仅用于设计问法，不作为事实结论：

- 澎湃新闻/秒针系统报道中提到，老乡鸡回应前，公众讨论集中在预制菜食品安全风险、消费者权益、配料、信息披露、权益保障和食品安全等方面。
- 人民网舆情数据中心相关分析提到，公众关注加工等级披露、半预制/复热标识、供应商公开和消费者知情权。
- 围绕 2026 年溯源报告 2.0 的公开报道强调了菜品分类、营养标识、检测报告、风险等级、线上可视化、二维码入口、供应商和配送透明。
- 预制菜相关微博和新闻讨论显示，消费者常对“预制菜”的定义有分歧，更在意清楚标识和知情选择。
